# Changelog

All notable changes to `pribandos` are recorded here, in the order they were committed. The format mirrors the Conventional Commits type and scope of the matching commit.

## [2026-08-26] — feat(library): dedicated /library/[slug] route with book-reading layout

- Replaced the home-page library popup modal with a dedicated per-book route. Clicking a spine on the home shelf now navigates to `/library/[slug]` instead of opening a modal overlay.
- Added `src/app/library/[slug]/page.js` (Server Component) and `src/components/BookReader.jsx` (sole client island) implementing a "reading a real book" layout: fixed parchment palette (paper `#fbf6ec`, ink `#2a1b15`, papyros texture, gilt top edge), drop-cap first paragraph, EB Garamond serif loaded route-locally, prev/next wrap-around pager, `← →` keyboard page-turning, reading-time in byline. Book surface stays parchment in both themes; only the chrome (frame, back link, pager cards) follows the home theme via `localStorage`.
- Expanded `libraryIndex` in `src/lib/data.js` from 3 placeholder records to a full 21-book bilingual catalogue (`{slug, titleEn, titleId, authorEn, authorId, year, summaryEn, summaryId, contentEn, contentId}`). Slugs generated by `slugify(EN_title)` so EN is canonical and ID titles resolve to the same URL.
- `Library.jsx` now renders all 21 books as `next/link` to `/library/[slug]` (was 3 buttons opening a modal).
- Removed `selectedBook` state and the modal block from `ClientPage.jsx`. Added a write-only `useEffect` mirroring `lang`/`isDarkMode` into `localStorage` so `BookReader` can pick them up on mount.
- Added `src/app/sitemap.js` (home + 21 book URLs) and `src/app/robots.js` (allow all + points to sitemap) for SEO. Per-book `generateMetadata` on the route exports title + ≤160-char description + OG/Twitter cards.
- Added translation keys (`backToLibrary`, `nextBook`, `previousBook`, `prevBook`, `pennedBy`, `readingTime`, `turnPage`, `volume`, `yearOfEra`) in both EN and ID `ui.*`.
- Why: the previous popup hid each book's content from search engines and made deep-linking impossible. Dedicated routes give 21 statically-generated, crawlable, linkable, pre-rendered pages with rich per-page metadata — the largest single SEO win on this site.
- Docs updated: `docs/overview.md` (intro, §2.1, §2.11, §2.14, §4, §6), `docs/features.md` (new file, Library section), `docs/architecture.md` (new file, route + data graph).

## [2026-08-26] — feat(blog): Travelling Scribe card grid + dedicated /blog/[slug] route

- Added a `#blog` home section (`BlogIndex.jsx`) rendering a card grid of posts fetched live from a Directus `blog_posts` collection (published only, sorted by `-published_at`). Renders an in-universe empty state when the collection is empty or unreachable.
- Added a dedicated `/blog/[slug]` Server Component (`src/app/blog/[slug]/page.js`) with `generateStaticParams`, per-post `generateMetadata`, and `notFound()`; `BlogPost.jsx` is the sole client island (share button, prev/next pager, keyboard `← →`, lang).
- Added `src/lib/blog.js` exporting `fetchBlogPosts()` — Directus fetch with `revalidate: 60`, normalized post shape, returns `[]` on any error. Consumed by the blog route and `sitemap.js`.
- Wired the fourth parallel fetch in `src/app/page.js` (`blog_posts`) and passed `blogPostsData` through `ClientPage.jsx` to `<BlogIndex/>`; added `blog` to the scroll-spy sections, nav entry (Feather icon), and mounted the section between Library and Party.
- Updated `src/app/sitemap.js` to async and appended blog URLs (`changeFrequency: 'weekly'`, `priority: 0.8`).
- Added translation keys (`nav.blog`, `sections.blog.*`, `emptyBlogTitle`, `emptyBlogBody`, `backToBlog`, `previousPost`, `nextPost`, `share`, `shareCopied`, `journalEntry`) in both EN and ID.
- Why: long-form content should be authored in the CMS without a redeploy, unlike the static local library. The blog lives on a live Directus collection with graceful degradation when empty.
- Docs updated: `docs/overview.md` (§2.15, §4, §6), `docs/features.md` (Blog section), `docs/architecture.md` (routes + data flow), `docs/changelog.md` (this entry).
- **Path correction**: route moved to `/Blogs/[slug]`.

## [2026-08-26] — fix(library): align mapper with live CMS field casing + sanitize HTML body

- Verified the live `https://cms.adit.dev/items/Blogs` response (Bearer auth) and discovered the field casing does not match what the previous `library.js` mapper expected. Real CMS shape: `Title`, `Content` (HTML), `Thumbnail`, `slug`, `date_created`, optional `Excerpt` — system fields are snake_case, content fields are PascalCase, consistent with the project-wide quirk in `AGENTS.md §4.3` (`Homepage`/`Projects` uppercase, `experiences` lowercase).
- Updated `src/lib/library.js`:
  - Endpoint now `/items/Blogs?sort=-date_created&filter[status][_eq]=published` (matches `page.js:21`).
  - Mapper reads `Title`, `Content`, `Thumbnail`, `slug`, `date_created`, optional `Excerpt`.
  - Added `contentParagraphs` — sanitized HTML split into top-level blocks (`<p>`, `<pre>`, `<div class="highlight">`, etc.) so the reading surface renders block-by-block via `dangerouslySetInnerHTML`.
  - Added a small sanitizer: strips `<script>`, `<style>`, `<iframe>`, `<object>`, `<embed>`, `on*` handlers, `javascript:` URLs. Keeps structural tags and `class` attributes so prose styles can apply.
  - Excerpt fallback: 180-char prefix of the plain-text body when `Excerpt` is unset.
- Updated `src/components/BookReader.jsx` to consume `contentParagraphs` and render each block via `dangerouslySetInnerHTML` instead of the old plain-text `\n\n` split. Drop-cap preserved on the first paragraph when it starts with text (not inline markup).
- Added `.book-prose` styles in `src/app/globals.css` for `<p>`, `<a>`, `<code>`, `<pre>`, `<ul>`/`<ol>`/`<li>`, `<blockquote>`, `<h2-4>`, `<strong>`, `<em>`, plus a drop-cap rule — all calibrated for the parchment palette so the HTML body sits comfortably on the paper.
- `src/app/page.js` was already calling `/items/Blogs` with the correct sort and filter from an earlier hand edit; no further change needed there.
- Why: the previous mapper returned undefined for every field, which left `Library.jsx` showing the empty state and `/library/[slug]` building with zero pre-rendered paths. With the field names corrected and the HTML body sanitized for safe innerHTML rendering, the build now pre-renders every published post.
- Verified: `npm run lint` — no new errors. `npm run build` — green, route table shows `/library/generate-excel-in-vue-js-using-excel-js` (the one published post at the time of this change), plus `/library/[slug]` as SSG.
