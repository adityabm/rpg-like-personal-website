# Architecture — Component Graph, Routes, Data Flow

## Routes

```
/                          (Server Component)  ── fetches Directus ──► <ClientPage/>
/library/[slug]            (Server Component)  ── resolves slug, fetches Blogs/{id} ──► <BookReader/>
/sitemap.xml               (Next.js sitemap.js)
/robots.txt                (Next.js robots.js)
```

- `/` is a **Server Component** (`src/app/page.js`). It fetches `Homepage`, `experiences`, `Projects`, and a lightweight `Blogs` index from Directus in parallel (`Promise.all`), each with `next: { revalidate: 60 }` for ISR. The index excludes the heavy `Content` HTML. On any error it silently falls back to the static data in `src/lib/data.js`.
- `/library/[slug]` is a **Server Component** (`src/app/library/[slug]/page.js`). `generateStaticParams` enumerates every published book slug from `fetchLibraryIndex()`, and `generateMetadata` uses the index; after resolving `slug → id`, the page fetches the full record with `fetchLibraryBookById(id)`. `dynamicParams = false` means unknown slugs are hard 404s.
- `/sitemap.xml` and `/robots.txt` are generated by the Next.js metadata-file conventions.

## Data flow

```
Directus (4 collections — Homepage, experiences, Projects, Blogs)
        │
        │  page.js fetches the light Blogs index with revalidate: 60
        ▼
<ClientPage />  (Client Component — state, theme, scroll-spy, dice)
        │
        │  receives `libraryBooksData` from page.js
        ▼
<Library />  (shelf on home, N next/link spines)
        │
        │  user clicks a spine
        ▼
/library/[slug]/page.js  (Server Component, slug → id, then fetchLibraryBookById(id))
        │
        ▼
<BookReader />  (Client island — lang/theme from localStorage, prev/next)
```

The library route now goes through Directus. `src/lib/library.js` exports `fetchLibraryIndex()`, which requests `GET /items/Blogs?fields=id,slug,Title,Thumbnail,date_created,date_updated&sort=-date_created&filter[status][_eq]=published` with `revalidate: 60`; it intentionally excludes `Content`. The home shelf, `sitemap.js`, `generateStaticParams`, and `generateMetadata` consume the normalized light index (`{id, slug, title, thumbnail, publishedAt}`). `/library/[slug]/page.js` resolves the public slug to an ID from that index, then `fetchLibraryBookById(id)` requests `GET /items/Blogs/{id}` for the full detail shape (`{id, slug, title, excerpt, thumbnail, publishedAt, readingMinutes, content}`). `Content` is HTML sanitized in `library.js` and rendered as one `dangerouslySetInnerHTML` subtree in `BookReader`, preserving nested code snippets and preventing hydration mismatches.

## State management

`ClientPage.jsx` owns the home page state:
- `lang`, `isDarkMode`, `scrollProgress`, `activeTab`, `diceRolling`, `diceValue`, `luckStatus`, `stats`, `screenEffect`.

A write-only `useEffect` mirrors `lang` and `isDarkMode` into `localStorage` so `BookReader` on the library route can pick them up on mount. This is a one-way bridge: the home page never reads from `localStorage`, the library route never writes back.

`BookReader` owns its own state:
- `lang`, `theme` (read from `localStorage` on mount, re-read on `storage` events so a future in-page toggle on the home page would propagate without a reload).

## Rendering model

| Surface | Server / Client | Why |
| --- | --- | --- |
| `/` entry (`page.js`) | Server | Directus fetch, ISR. |
| `<ClientPage>` | Client (`'use client'`) | Holds scroll, theme, dice, and navigation state. |
| `<Library>` | Server-rendered (no `'use client'`) | Pure render of `libraryBooksData`; empty state when no books. |
| `/library/[slug]/page.js` | Server | Pre-rendered, per-page metadata, no JS shipped for the route itself. |
| `<BookReader>` | Client (`'use client'`) | `localStorage` reads, keyboard handlers, the only island on the route. |
| `<Sitemap>`, `<Robots>` | Next.js framework | Generated at build. |

## Theme model

Dark mode is **hand-rolled**. There are no `dark:` Tailwind variants anywhere in the codebase. The theme is owned by `ClientPage` and applied as conditional class ternaries on the home page. The library route reads the theme from `localStorage` and applies it conditionally to the chrome only — the book surface is fixed parchment regardless.

## Library data flow in detail

```
Library home/sitemap/static params ──► fetchLibraryIndex() ──► /items/Blogs?fields=... (no Content)
/library/[slug] ──► slug → id from index ──► fetchLibraryBookById(id) ──► /items/Blogs/{id}
```

```text
Directus `Blogs` collection (published rows, sorted by -date_created)
        │
        │  fetchLibraryIndex() with revalidate: 60; fields exclude Content
        ▼
normalized index ({id, slug, title, thumbnail, publishedAt})
        │
        ├──► <Library /> (home shelf)            — iterates, renders N next/link spines
        │
        ├──► /library/[slug]/page.js             — generateStaticParams enumerates slugs
        │       │                                 — generateMetadata builds per-book SEO
        │       │                                 — resolves slug → id
        │       └──► fetchLibraryBookById(id)     — GET /items/Blogs/{id}
        │                                             sanitizes Content HTML
        │                                             ▼
        │                                         <BookReader /> — one HTML subtree
        │
        └──► sitemap.js                          — produces N sitemap entries
```

Adding a book is now a CMS operation: create and publish a row in the `Blogs` collection with `status=published` and a slug, and it appears on the next ISR cycle (60s) — the home shelf auto-renders, the page auto-generates, and the sitemap auto-publishes. No redeploy needed.
